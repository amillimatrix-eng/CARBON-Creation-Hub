# RGR ADDENDUM — EXECUTOR FAILURE MUST NOT BLOCK OBJECTIVE

Date: 2026-10-07
Trigger: Repeated failure to apply an accepted operational learning after it was explicitly identified by Owner.

## Evidence / failure
The Matrix identified and accepted the learning that BLACK is an auxiliary, replaceable executor and must not gate revenue or bounty execution when lawful alternatives exist. Despite that learning, subsequent Reaper handling again described BLACK as UNKNOWN/HOLD and left the executable bounty consequence unproduced instead of routing the work through another authorized execution surface.

This repetition converts the prior learning into an RGR event: the issue is no longer first discovery; it is failure to retain/apply the discovered routing rule.

## Binding correction
1. Objective continuity outranks executor continuity.
2. BLACK, Render, GitHub-native execution, cloud runtimes and other authorized execution surfaces are resources, not owners of work.
3. If the preferred executor is unavailable and another lawful route can perform the parcel, route around the unavailable executor immediately.
4. BLACK degradation must not block iSCOPE, PRI, or Bounty Reaper core work.
5. Repair BLACK asynchronously with bounded effort unless a task has an evidenced BLACK-unique dependency.
6. Market/revenue execution receives higher allocation than perfecting replaceable infrastructure because revenue can acquire additional execution capacity.
7. Do not classify an unavailable executor as a reason for work inactivity when an authorized alternative exists.
8. A watcher that detects this condition must advance the objective through an alternative route or identify the exact unique dependency preventing that route; repeated observation is insufficient.

## Acceptance
BLOCKED EXECUTOR -> ALTERNATE AUTHORIZED ROUTE -> EXECUTION -> MATERIAL STATE CONSEQUENCE -> DURABLE EVIDENCE -> NEXT WAKE CONSUMES NEW STATE.

Infrastructure repair is a separate lane and is not closure for the blocked objective.

## RGR closure rule
No closure from prompt/configuration edits alone. Closure requires evidence that a real blocked parcel was routed around an unavailable/nonessential executor and produced a material consequence.

## Scope
This addendum records the routing/retention failure. It does not delete BLACK, reduce Reaper capability, create duplicate workers, or widen authority.
