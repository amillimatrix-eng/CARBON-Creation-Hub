## 4. MASTER INDEX IMPLEMENTATION

Do not create a separate permanent stamp registry.

Extend the existing Master Index / artifact metadata with FORX fields.

Recommended minimum fields:

- `FORX_MARK`
- `FORX_CYCLE_STATE`
- `FORX_REVIEW_REF`
- `FORX_VERSION_REF`
- `FORX_LAST_REVIEWED`

### FORX_MARK

Values:

- `REQUIRED`
- `ACTIVE`
- `EXEMPT_RAW_EVIDENCE_INLINE_ONLY`

All governed artifacts should be represented as FORX-visible in Index metadata.

### FORX_CYCLE_STATE

Administrative states only:

- `OPEN`
- `REVIEWED_NO_ACTION`
- `RECTIFICATION_OPEN`
- `VERIFIED_CURRENT_VERSION`
- `REVERIFY`
- `SUPERSEDED`

These are not lifecycle states.

### FORX_REVIEW_REF

Points to the current FORX packet / verification receipt / review record.

### FORX_VERSION_REF

Binds FORX review to the exact artifact version, commit/hash, or equivalent immutable source reference.

### FORX_LAST_REVIEWED

Records review time when reliable.

---

## 5. VERSION-BOUND FORENSIC ASSURANCE

A FORX mark is valid only for the version reviewed.

Any material content change, amendment, merge, supersession, or implementation consequence triggers:

> **FORX_CYCLE_STATE → REVERIFY**

Therefore:

> **VERIFIED ONCE ≠ VERIFIED FOREVER.**

This prevents stale forensic clearance from attaching to later changed logic.

## 6. NEW ARTIFACT RULE

For new governed artifacts created after authorization of this control:

- primary authority/owner identification remains mandatory;
- FORX mark metadata is added at creation;
- default state is `OPEN`;
- artifact enters normal lifecycle independently;
- FORX review may occur immediately or through normal dependency-weighted queueing.

The presence of `OPEN` does not block the artifact unless an existing rule requires forensic completion before its next lawful transition.

This B-priority control must not invent a universal new hard gate unless Governance explicitly authorizes one.

Do not mass-edit historical source artifacts merely to add a badge.

Historical coverage is achieved through:

1. Master Index metadata overlay;

This preserves:

- original chronology;
- historical source fidelity.

No provenance destruction for cosmetic consistency.

## 8. RAW EVIDENCE RULE

Raw evidence must not be modified just to insert a FORX mark.

Examples:
- screenshots;
- original transcripts;
- third-party files;
- receipts;
- raw logs;
- immutable hashes;
- source archives.

For raw evidence, attach the FORX mark externally in Master Index / provenance metadata.

Principle:

> **STAMP THE RECORD ABOUT THE EVIDENCE, NOT THE EVIDENCE ITSELF.**

## 11. AUTONOMOUS LOOP

The FORX mark exists to keep the loop continuing.

Typical loop:

**ARTIFACT CREATED / CHANGED  
→ FORX OPEN  
→ FORENSIC REVIEW  
→ NO ACTION or RECTIFICATION PACKET  
→ EXISTING OWNER RESOLVES  
→ FORX-V VERIFY  
→ VERIFIED_CURRENT_VERSION  
→ MATERIAL CHANGE  
→ REVERIFY**

The loop is event-driven and weighted.

It must not create infinite re-review without a material trigger.
