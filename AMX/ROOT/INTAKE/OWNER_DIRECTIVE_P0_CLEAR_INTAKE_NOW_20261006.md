## WHAT “CLEAR” MEANS

Clearing intake does **not** mean deleting, hiding, bulk-merging, or silently promoting records.

Every governance-ready intake item must receive one explicit durable disposition:

- **MERGE**
- **MODIFY**
- **REJECT**
- **ALREADY-SUBSUMED**
- **HOLD** — only where a concrete unresolved authority/evidence/dependency condition genuinely prevents disposition.

For every disposition, record:

1. artifact / stable intake identifier;
2. current lifecycle state;
3. final governance disposition;
4. exact governing source/control;
5. exact existing owner;
6. exact destination;
7. duplication/supersession relationship;
8. Canon impact;
9. Build impact;
10. Master Build File impact, if any;
11. required implementation consequence;
12. exact next action;
13. behavioral/acceptance or closure standard;
14. unresolved dependency, if HOLD;
15. provenance/readback receipt.

## NO GENERIC DEFERRAL

The following are **not** valid reasons to leave a governance-ready item pending:

- “needs more review” without naming the missing evidence;
- “candidate” merely because it arrived recently;
- operational busyness elsewhere;
- duplicate terminology;
- uncertainty that can be resolved from existing sources;
- waiting for another transcript;
- waiting for Owner restatement of an already explicit directive;
- preserving a queue item merely because it has historically remained in intake.

If evidence is genuinely insufficient, use **HOLD** with the exact missing evidence/dependency and the owner responsible for resolving it.
