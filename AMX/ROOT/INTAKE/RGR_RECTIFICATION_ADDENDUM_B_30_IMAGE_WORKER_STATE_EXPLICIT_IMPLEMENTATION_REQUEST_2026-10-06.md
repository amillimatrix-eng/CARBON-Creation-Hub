## Owner request

The **30-image state of the workers** is to be made explicit in the implementation path for the DR-0021 recovery.

This is not a request to infer a new system from the number 30. It is a request to preserve and explicitly re-establish the worker state associated with the previously demonstrated commercial-intelligence behavior in which the 30-image state was part of the evidenced operating condition.

## Relationship to DR-0021

Addendum A identifies the regression surface as:

**GLOBAL INTELLIGENCE → PROBLEM-INSTANCE REASONING → OFFER GENERATION → EXTERNAL COMMERCIAL ACTION → STATE RETENTION → CONVERSION.**

This Addendum B adds the explicit implementation requirement that the worker-side **30-image state** associated with that demonstrated capability must not remain implicit, transcript-only, or dependent on model recollection.

It must be represented durably enough that authorized workers can recover the intended state without reconstructing it from conversation history.

## Infrastructure-first requirement

Before implementation, the owning stream must determine:
1. whether an existing worker-state, capability-state, context-state, evidence-state, or continuity mechanism already owns this responsibility;
2. whether the 30-image state is a retained context set, evidence set, activation state, capability preload, working-memory state, or another already-governed object;
3. whether the exact 30-image composition/order/selection is already recoverable from durable evidence;
4. what worker(s) require access to that state;
5. what persistence boundary is required across continuation, handoff, restart, and worker replacement;
6. what acceptance test proves the state has been restored behaviorally.

No new parallel architecture is authorized if an existing owner can absorb the requirement.

## Exactness / anti-invention boundary

The current intake evidence supports that **“30 images” is a material anchor of the prior demonstrated worker state**.

The current repository evidence does **not yet independently establish the exact implementation semantics** of that state, including:
- the authoritative list of the 30 images;
- whether order matters;
- whether all 30 must be simultaneously present;
- whether the state is visual context, learned context, evidence context, prompt context, or another governed representation;
- whether the same 30 apply identically to every worker.

Therefore implementation must first recover those exact semantics from the underlying evidence/transcript/artifact chain. UNKNOWN must remain UNKNOWN until recovered.

## Required implementation outcome

Once the exact semantics are recovered and governance/build authority permits implementation, the worker state must be explicit rather than implicit.

At minimum, the implementation should make durable and testable:
- the authoritative reference to the recovered 30-image state;
- ownership;
- worker applicability;
- lifecycle/persistence behavior;
- restoration behavior after continuation/handoff/restart;
- provenance to the recovered source material;
- acceptance evidence showing that the commercial-intelligence behavior survives with the state restored.

## Acceptance relationship

Restoration is not proven merely because 30 image references exist.

The behavioral acceptance test must still demonstrate the DR-0021 chain:

**GLOBAL INTELLIGENCE → PROBLEM-INSTANCE REASONING → OFFER GENERATION → EXTERNAL COMMERCIAL ACTION → STATE RETENTION → CONVERSION.**

The 30-image state is therefore an explicit implementation requirement and recovery dependency, not a substitute for behavioral acceptance.

## Scope boundary

Route to the existing owning governance/build stream to:

4. update the Master Build File if implementation becomes authorized for V1;
