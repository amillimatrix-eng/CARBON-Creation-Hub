## 3. What we learned

1. The capability estate is now substantially broader than the old “one chat + browser + terminal” model.
2. The strongest new advantage is not any single plugin; it is composability:
   research -> grounded evidence -> governed artifact -> code/design -> deploy -> inspect -> sales action -> receipt.
3. Skills are materially useful because they provide specialist operating procedures, not merely new buttons.
4. User-created skills/templates can preserve AMX-specific doctrine and formatting so repeated work no longer starts from generic model behavior.
5. The Matrix must distinguish:
   INSTALLED / AVAILABLE / AUTHENTICATED / EXECUTED / VERIFIED.
   Today exposed several cases where installed or authenticated capability was incorrectly at risk of being treated as executed capability.
6. Work Mode dependencies matter. Some high-value skills, especially Product Design and Data, achieve their intended end-to-end capability only in Work Mode.
7. Cloud/GPU capability is wider now, but several routes can incur cost. Under the current scarcity posture, paid compute must not displace near-term income unless it is a proven dependency.
8. More connectors increase authority surface and possible state fragmentation. This strengthens the case for the new mandatory run-outcome/intake bridge rather than weakening it.

- Better direct execution in source systems instead of copy/paste.
- Better sales method and commercial artifact quality through Sales skills.
- Better visual/product execution through Product Design + Figma.
- Better deployment and debugging through Vercel + Render + GitHub.
- Better data/system backend capability through Supabase and Data skills.

- Better low-cost opportunity triage through bottom line.
- Better evidence continuity because manual packages are now durably preserved rather than living only in chat.

## 5. Net disadvantages / risks

- Capability bloat: more tools can create unnecessary parallel workers or duplicate flows.
- Permission/auth fragmentation: installed does not mean connected, authenticated, writable or executable for every action.
- Surface-specific limitations: some skills require Work Mode or a specific tool environment.
- Cost exposure: Hugging Face Jobs, cloud compute, paid SaaS actions and provider usage can burn scarce funds.
- Operational drift: generic Sales/Product Design/Data skills can conflict with AMX role boundaries if treated as new owners instead of support capability.
- Evidence inflation: tool availability can be mistaken for completed work.
- Security/credential exposure expands with each connector and device authentication.
- More surfaces increase the cost of keeping state synchronized unless the run-outcome/intake bridge is enforced.
