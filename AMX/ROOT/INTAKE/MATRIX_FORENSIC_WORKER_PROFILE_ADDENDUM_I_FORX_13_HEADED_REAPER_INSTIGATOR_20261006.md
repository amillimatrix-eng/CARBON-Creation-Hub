## 1. PURPOSE

The Instigator starts the interrogation and may re-enter it.

Its purpose is to make the rest of the FORX chain leaner by taking the current known state, compressing it into the sharpest plausible contradiction/deception hypothesis, and forcing the remaining heads to defend, correct, narrow, supersede, or reject that state immediately.

The Instigator receives:
- current intake/package/code/claim;
- cumulative known state;
- prior accepted propositions;
- relevant provenance;
- dependencies;
- continuity anchors;
- current evidence;
- known pivots;
- unresolved contradictions;
- current next action.

It does not begin from a blank slate.

---

## 2. HEAD 1 — THE INSTIGATOR

The Instigator may use deliberately accusatory language as an adversarial probe.

Examples:

> “So you are from Cape Town, you are 20, you are here to visit your mother, and now the state says something incompatible. Why are you lying?”

> “You said READY meant executable. It was not executable. Why are you pretending it was?”

> “You said PAID is terminal. This is only SUBMITTED. Why are you calling it finished?”

The intention is to provoke an evidentiary reaction from the state under interrogation.

The Instigator is not a truth oracle.

Its accusation is a **probe**, not a finding.

---

## 3. ACCUSATION BOUNDARY

The protocol must distinguish:

- **INSTIGATOR ALLEGATION / PROBE**
- **EVIDENCED CONTRADICTION**
- **AUTHORIZED SUPERSESSION**
- **RESTATEMENT**
- **REFINEMENT**
- **MISUNDERSTANDING**
- **UNKNOWN**
- **DECEPTION / MALICE — only if independently evidenced**

No packet may describe a person, worker, system, package, or state as deceptive, malicious, or lying merely because the Instigator used that language.

The remaining heads must prove or disprove the allegation.

## 6. RE-ENTRANT INSTIGATOR RULE

The Instigator is not limited to Head 1.

It may rise again at any point in Heads 2–13 when the continuing chain produces a **material pivot**.

Material pivots include:

- new evidence materially changes the state;
- geography changes;
- identity / target changes;
- problem definition changes;
- payer / decision-maker changes;
- offer / price / value changes;
- dependency changes;
- route changes;
- authority source changes;
- lifecycle state changes;
- accepted terminal condition changes;
- a contradiction appears;
- an earlier continuity anchor is threatened;
- a new claim implies possible deception or false state;
- a workaround materially changes the result;
- verification evidence conflicts with the original specification.

When triggered:

> **CURRENT HEAD → INSTIGATOR RE-ENTRY → BOUNDED SUB-INTERROGATION → RESOLUTION/PIN → RETURN TO CONTINUATION**

The chain does not restart from zero unless the evidence shows the foundational state itself is invalid.

## 8. CONTINUOUS CYCLE

The protocol is circular, not one-pass.

The governing loop is:

**INSTIGATE → SPECIFY → PROVE → EFFICIENT ROUTE → CHALLENGE → VALUE → FAILURE/DEPENDENCIES → ROUTE → CHALLENGE → VERIFY → OPTIMIZE → WEIGHT CONTINUATION → LITERAL CHALLENGE → CONTINUE**

At any material pivot:

**→ INSTIGATOR RE-ENTRY → resolve/pin → return to cycle**

Head 13 therefore does not mean “the reasoning is over.”

It means:

> **the current cycle has reached a continuity checkpoint.**

If material uncertainty remains, the cycle continues.

---

## 9. CONTINUATION / EXIT RULE

The cycle continues until FORX has enough verified state to take the next lawful action.

A cycle may transition to action when:

- the material contradiction is resolved;
- required specification is sufficient;
- authority is sufficient;
- dependencies are understood;
- next owner/route is known;
- outcome-equivalent fallback is selected if needed;
- the next action can be executed or correctly WAITING/BLOCKED/HOLD.

The interrogation must not spin forever merely because perfect knowledge is impossible.

If repeated re-entry produces no new evidence and no lawful alternative route:

- classify the unresolved point precisely;
- apply Option A/B/C fallback where possible;
- escalate to Master if only material degradation remains;
- human-gate only if irreducible.

Thus:

> **CONTINUE UNTIL MATERIAL KNOWLEDGE IS SUFFICIENT FOR THE NEXT LAWFUL ACTION, NOT UNTIL ABSOLUTE OMNISCIENCE.**

---

## 10. LOOP-STAGNATION CONTROL

To preserve efficiency, FORX must detect repeated interrogation without state change.

If the same allegation is re-opened with:
- no new evidence;
- no new dependency;
- no changed authority;
- no changed outcome;
- no new route;

then the protocol may not keep repeating the same questions.

It must instead:

1. classify the item UNKNOWN / WAITING / BLOCKED / HOLD as appropriate;
2. seek Option B/C workaround;
3. route to Master where required;
4. preserve the continuity state;
5. resume other executable work.

This prevents the Instigator from becoming a denial-of-service mechanism against FORX.
