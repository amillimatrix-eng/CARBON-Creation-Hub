### Anti-backdoor invariants

**DEPENDENCY != AUTHORITY.**

**BLOCKER != INSTITUTION.**

**UNRESOLVED TOOLING != GOVERNANCE PROMOTION.**

A connector, plugin, account, workspace, credential, provider, runtime, browser, API, or other capability dependency may block only the action that actually requires it. It may not:
- create or preserve a new governance object;
- broaden a classification into an institution;
- confer execution authority;
- justify a new worker, manager, queue, scheduler, dashboard, or state machine;
- convert a temporary HOLD into a standing Matrix role;
- close or validate an unrelated governance question.

If a dependency cannot be resolved on the current surface, the required continuation is:
**SCOPED HOLD -> DURABLE INTAKE HANDOFF -> GOVERNANCE VISIBILITY -> RESUME WHEN SATISFIED.**

The handoff must state the blocked action, exact dependency, evidence, scope of HOLD, furthest evidenced state, next permissible action, and what remains unaffected.

### RGR lifecycle

RGR has no independent persistent life.

An RGR incident, if governance accepts the classification, is attached to the underlying governed failure and follows:
**OBSERVED -> MAPPED_TO_EXISTING_CONTROL -> ENFORCEMENT_CAUSE_IDENTIFIED -> CORRECTED -> BEHAVIOR_RETESTED -> CLOSED.**

If behavior has not been retested, the incident is not closed.

Closing an RGR incident does not remove or supersede the underlying governing control.

### Severity

RGR classification and severity are separate.

A repeated low-impact presentation/duplication failure and a repeated security/privacy/authority failure may both qualify structurally as recurrence, but their severity must be determined by consequence, exposure, reversibility, affected scope, and governing domain. RGR must not automatically inflate severity.

### CEF escalation

Do not escalate merely because a failure happened twice.

**CONTROL ENFORCEMENT FAILURE (CEF)** is justified only when:
1. the governing control already exists;
2. an enforcement or acceptance mechanism was actually applied;
3. that mechanism was exercised or behaviorally tested;
4. materially equivalent failure recurs afterward.

CEF therefore means the problem is no longer policy absence; the enforcement path itself has failed to bind execution.
