## Recovery gate
Before any consequential claim or change to an ecosystem's identity, purpose, architecture, ownership, market proposition, capabilities or relationship:
1. recover authoritative repository/package/governance/deployment evidence;
2. establish source lineage and supersessions;
3. separate SOURCE / DEPLOYMENT / RUNTIME / CURRENT STATE;
4. test proposed interpretation/change for dilution;
5. classify unresolved relationships UNKNOWN/HOLD rather than infer;
6. only then execute or modify.

A model's conversational memory is not authoritative custody.

## Reactivation semantics
A held ecosystem is not reconstructed from the current model's memory.
Recovery sequence:
RECOVER ECOSYSTEM -> VERIFY AUTHORITATIVE STATE -> RESOLVE SUPERSESSIONS -> PRESERVE IDENTITY/CAPABILITY -> IDENTIFY DELTAS -> ADD ONLY NON-DILUTING CHANGES -> RESUME.
