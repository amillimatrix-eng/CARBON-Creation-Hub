## 1. PRODUCT THESIS

CARBON° is one product family with one common operating spine.

- CARBON° Search / INTELLAGENT = Engine of Intent.
- CARBON° Marketplace = Market of Intent.
- CARBON Studios = Fulfilment / creation / production layer.
- AMilliMATRiX = continuity, governance, evidence, routing, trust and durable operating memory.

Unified loop:

INTENT → RESOLUTION → MATCH / ROUTE → CREATE / FULFIL → DELIVER → OUTCOME → LEARNING → UPDATED INTENT / MARKET SIGNAL.

Search is not an isolated search box. Marketplace is not an isolated listing board. Studios is not an isolated production shop. Matrix is not an isolated control plane.

The product advantage comes from the joins.

## 6. STORAGE AND DATA MODEL

Default product stance:

USER OWNS SOURCE CONTENT AND BUSINESS DATA.

CARBON may store only what the user authorizes and what the product needs to operate, subject to retention policy and applicable law/provider terms.

### Storage modes

A. CARBON-HOSTED
- default convenience tier;
- object storage for media;
- database for metadata;
- controlled retention;
- deletion/export controls.

B. BRING-YOUR-OWN STORAGE
- premium / business / privacy-sensitive;
- user-controlled cloud bucket / Drive / Dropbox / equivalent;
- CARBON stores references, metadata, permissions and receipts as needed.

C. LOCAL-FIRST / MINIMAL RETENTION
- privacy-sensitive workflows;
- local/client retains primary files;
- CARBON stores only minimal operational metadata where feasible;
- some continuity/search features may be reduced.

### Architecture
- Frontend: existing web surface / Vercel-compatible delivery.
- Backend: existing CARBON FastAPI substrate.
- Metadata: current evidence/state store for V1, production-grade DB when scale requires.
- Media: object storage; do NOT treat Vercel static hosting as the media vault.
- Permissions: ACL-aware object references.
- Provenance: provider/model/request/job/artifact identity, rights/commercial-use state.
- Retention: configurable and explicit.
