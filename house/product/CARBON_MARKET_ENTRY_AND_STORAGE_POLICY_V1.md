# CARBON° MARKET ENTRY + STORAGE / DATA POLICY V1

Date: 2026-10-09

## PRODUCT PROMISE

CARBON° should make search, creation, marketplace packaging and action feel like one continuous experience.

## DATA OWNERSHIP

Default principle:
**THE USER OWNS THEIR SOURCE CONTENT AND BUSINESS DATA.**

CARBON does not acquire ownership merely because content is uploaded, generated, indexed or routed through the service.

Generated-output ownership remains subject to:
- applicable law;
- provider terms;
- third-party rights;
- client contract;
- source/reference rights.

## RETENTION MODES

### Standard / hosted
CARBON-hosted object storage + metadata.
User can delete/export according to final governed policy.

### Business / BYO
Customer-controlled external storage.
CARBON stores references, permissions, searchable metadata and receipts needed to operate.

### Privacy / minimal retention
Primary files remain client/local where feasible.
CARBON retains minimum operational state.
Feature availability may be reduced.

## MEDIA

Images: supported in V1 routed experience.
Short video: supported in V1 bounded experience.
Voice/audio: supported in V1 bounded experience.
Long-form production: studio/beta workflow until separately proven.

## STORAGE IMPLEMENTATION

Media files belong in object storage.
Metadata/session/provenance belong in database/evidence storage.
Frontend hosting is not the canonical media vault.

Required object record:
- artifact_id;
- owner/workspace;
- storage mode;
- object locator;
- MIME/type;
- size;
- created_at;
- retention class;
- visibility/ACL;
- provider;
- model;
- request/job ID;
- rights/commercial-use state;
- provenance;
- hash where available.
