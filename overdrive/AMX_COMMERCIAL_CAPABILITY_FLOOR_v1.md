# AMX COMMERCIAL CAPABILITY FLOOR v1
Effective: 2026-10-01
Status: ACTIVE — AUTHORITATIVE COMMERCIAL DISCOVERY INPUT

## Purpose
Give iSCOPE and PRI an explicit company-capability floor so commercial discovery does not depend on a worker guessing what AMilliMATRiX can do. This is a floor, not a ceiling. New capability adds; it does not erase. UNKNOWN/HOLD beats inference.

## Evidence classes
- VERIFIED/CURRENT: directly supported by current durable evidence.
- EVIDENCED/HISTORICAL or REMEDIATE: real capability/product evidence exists but current deployment/runtime must not be overstated.
- OWNER-ESTABLISHED COMMERCIAL CAPABILITY: established company/operator capability accepted for discovery, but specific external claims/deliverables must be evidenced before proposition.
- DERIVED APPLICATION: a new sellable use produced by combining evidenced capabilities. It becomes a commercial candidate only after the match and deliverable are evidenced.

## Capability floor

### 1. Software, web, automation and technical systems
AMX may discover work requiring software engineering, web/full-stack implementation, automation, workflow/agent design, API/integration work, technical troubleshooting/support, data/evidence processing, testing and implementation where the required stack/outcome can be evidenced before commitment.
Commercial rule: do not claim an unverified technology-specific capability merely because it resembles known work.

### 2. AI/system evaluation, adversarial testing and falsification
AMX may discover authorized AI evaluation, model/agent testing, red-teaming, robustness/falsification, governance-system challenge work, synthetic test construction, evaluation design and evidence-based failure analysis.
Only test/break systems inside explicit published authorization/scope.

### 3. QA and automated testing
AMX may discover software QA, test design, automated checks, synthetic defect fixtures, regression/acceptance testing, app/web evaluation and related quality-engineering work.
Commercial precedent: Ecognix synthetic JavaScript demonstration — 16 checks, three seeded defect groups, corrected fixture passing 16/16, no Ecognix data or credentials. The opportunity did not convert, but it evidenced a derived commercial application of existing technical/evaluation capability.

### 4. Durable workflow, governance and evidence systems

Potential work includes workflow/state-machine design, evidence/provenance systems, automation controls, operational QA and process integrity where fit is evidenced.

## Capability-to-market discovery duty
iSCOPE MUST reason beyond named opportunity categories using both directions:
1. CAPABILITY -> NEW APPLICATION -> POSSIBLE PAYER -> EVIDENCED DEMAND -> OPP-ID.
2. MARKET SIGNAL -> REQUIRED OUTCOME -> CAPABILITY MATCH/COMBINATION -> EVIDENCED DELIVERABLE -> OPP-ID.
3. OBSERVED ORGANIZATION PROBLEM -> AMX SOLUTION/RESULT -> CREDIBLE BUYER -> DIRECT-SALE OPP-ID, even where no job/bounty/listing exists.

The known opportunity-category list is a search floor, not an ontology and not a ceiling.

## Commercialization gate
Before PRI externally represents a derived/new capability:
- identify the exact capability combination;
- identify authoritative evidence or create an authorized synthetic/demo proof without using counterparty private data/credentials;
- state what AMX can actually deliver;
- preserve UNKNOWN/HOLD for unsupported portions;
- then proposition/submit under ONE PRI.

## Payment rails
Recover overdrive/payment_rails.json before rejecting an opportunity for payment incompatibility. Payment methods are additive and non-exhaustive. Program-provided/bound wallets are a separate onboarding case.

## Falsification
Commercial discovery has drifted if:
- iSCOPE searches only categories literally named in its prompt;
- a demonstrable AMX capability has no path into market discovery;
- new market demand cannot produce a new OPP-ID unless pre-enumerated;
- a worker invents capability instead of evidencing it;
- current runtime/deployment is inferred from historical product evidence;
- PRI waits for Owner to identify the revenue stream.

## Execution standard
